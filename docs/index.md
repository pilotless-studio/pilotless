# pilotless

Most of what a first manager does is ask people what they did this week and write it down. That part is automatable.

- **[Weekly status pages](status/)** - a worked example: what shipped, who moved code, which pull requests have gone quiet and which issues nobody has picked up, for 18 well-known public repositories. Regenerated every Thursday, unofficial, removable on request.
- **[pilotless status](https://github.com/pilotless-studio/pilotless)** - the GitHub Action that produces those reports inside your own CI. Two lines of YAML, no account, no API key, nothing leaves GitHub.
- **[What this is trying to be](https://pilotless-web-o53cqe2tiq-ew.a.run.app/?src=directory.r1)** - the project page.

Every decision this project has made is written down, with the reasoning as it was at the time, in [DECISIONS.md](https://github.com/pilotless-studio/pilotless/blob/main/DECISIONS.md).
